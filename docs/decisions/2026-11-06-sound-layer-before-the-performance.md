# Before the performance the signal changes only as a sound layer; then the code is frozen

Status: decided (owner 2026-11-06: "D kommt vor B. In der ersten Dez Woche", and "ja, D so ok" to a sound layer that
leaves detection as it is)
Date: 2026-11-06

## Decision

In the first week of December (roadmap-0-steps.md step 24, 2026-12-01 .. 12-06) the signal gets OUT-006's aesthetic
layer and BEH-006's variation over time, with PAR-009's params as far as they need them, as a layer that changes the
sound and leaves the detection layer as it is. After that step the code is frozen until the performance on
2026-12-13: params and fixes for real faults only.

## Why

- The room with all nodes opens on 2026-12-07 and the performance is on 2026-12-13: six days for the field, the demo
  and a rehearsal. A detection change in that week would leave the November measurements (13.1, 15, 20.4) behind.
- The two-layer signal (OUT-006) exists for this: the aesthetic layer changes what is heard, the detection layer
  what the nodes hear.
- A sound change before the baseline with all nodes (18) keeps that baseline the performance's.

## Rules out

- DET-014, BEH-007, min_island_count or any change to the detection layer before the performance.
- A tuning pass in the room: margins are set there by PARAM SET only (DET-019 comes after).
- New features after 2026-12-06.

## Revisit when

The sound layer cannot be built without touching detection: then the performance keeps today's signal and the
layer waits for the time after it.
