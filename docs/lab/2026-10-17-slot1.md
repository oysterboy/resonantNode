# 2026-10-17 slot 1 (unsupervised bench): the deafness wanders; after the replug nothing crosses

Status: observations; data in `bench/sessions/2026-10-17-slot1-e3-listener` (README has the run table).
Previous: `2026-10-16-bench-day.md` section 10 (E3 "deaf" the evening before).

- **E3 is not a bad listener.** It heard again in the morning (every kick answered, 25 of 29 idle calls). Then E2 was
  deaf for ten minutes (3 of 38), heard again on the old build (8 of 9) and on the new build (12 of 13), so there is
  **no regression from the 2026-10-16 merge**. Later E3 went deaf from minute 4 of a run. The deafness moves between
  boards and builds and lasts minutes.
- **Diagnostics added to the Node's `RB STATUS`** (82710e8): suppression armed/until/now, suppressed sample count,
  sample clock against the system clock, chirp active, plus the audio-health fields from the morning. In the deaf
  run with these fields E2 showed nothing wrong: suppression accounted exactly for its own idle calls, the sample
  clock sat a constant 58 ms behind the system clock, the chirp output never stuck. So the own-emit path is not the
  cause, at least for E2.
- **The Node loses DMA buffers**: 0.3-0.4 per second (8 ms each) in every run today, logging on or off, stream
  otherwise whole (99.9 % of samples). The Analyzer batteries of 2026-10-16 counted zero. Unexplained; an 8 ms hole
  in a 165 ms train is bridged by the gap logic, but bursts would not be.
- **After the owner replugged the USB cables (ports changed) both nodes were deaf for ten minutes**, and a cross-path
  check (E2 Analyzer, OBS windows, E3 playing ten SELFTEST chirps) saw only two 4-7 ms fragments at strength ~2,400
  where the same path gave full chirps at 5,000-9,000 the day before. The placement changed; to be restored and
  verified by the owner before any further listening test. The wandering deafness before the replug is still open.
- `nodepair.py` gained `--a-setup/--b-setup` (settings inside the run; a port open resets the board) and
  `--status-every` (audio health per node over the run). A SELFTEST chirp is a poor kick: the self-test's 300 ms echo
  window keeps the kicking node from hearing the answer. A manual network-signal command on the Node is the better
  kick (not built).
